## 1. 结论

第五次测试证明当前系统在“模型成功返回并形成 Candidate”时已经能够稳定给出
正确答案：已评分的 75 个成功输出经类型感知评分后为 75/75。然而，本轮不能
通过 Phase 7 冻结门禁，因为批次只落盘 82/88 题，成功状态为 75/82，模型
派发成功率仅为 129/208，且第 80 题的超长错误 `final_answer` 在公共写盘时
触发了未隔离的 `ValueError`，导致整个 runner 提前终止。

因此，本报告只支持“质量链路已有明显进步、稳定产出链路仍未达标”的结论，
不支持把 Competition 配置标记为 `live-validated` 或 `frozen`。

## 3. 批次提前终止的直接原因

运行清单最终状态为 `failed`，失败类型为 `ValueError`。第 80 题的 Primary
返回没有满足 Candidate JSON 契约，Parser 以 `answer_recovered` 恢复时把
约 20,287 个字符的完整解题文本错误地识别为 `final_answer`。虽然同题的
Alternative 已严格解析并给出正确答案 `1/16`，旧 Admission 与 Arbitration
仍允许超长 Primary 进入并在实质排序并列时选中它。

Runtime 随后生成约 20,301 字符的 `final_response`，超过 20,000 字符公共
上限。`write_case_output()` 的异常未按题隔离，因此已完成求解的 83、84、
85 题也没有写成公共 JSON，86、87 题没有启动。Debug Journal 显示：

| ID | Harness 终态 | Harness 耗时 |
|---:|---|---:|
| 80 | `primary` | 281.564 秒 |
| 83 | `primary` | 315.921 秒 |
| 84 | `primary` | 73.725 秒 |
| 85 | `primary` | 216.861 秒 |

这不是模型本身没有返回，而是 Candidate Admission、最终选择和公共写盘之间
缺少同一条可执行长度契约。

## 4. 评分复核

初次画像把三个等价答案误判为错误：

- `-\pi i` 与 `-i\pi`；
- `\{\lambda\in\mathbb C:|\lambda|\le1\}` 与 Unicode 等价集合；
- `(16/19,15/19)^T` 与 LaTeX 列向量
  `\begin{pmatrix}16/19\\15/19\end{pmatrix}`。

类型感知评分器现已补齐虚数乘法、Unicode 数域和 LaTeX 行/列向量归一化。
修正后第五次测试的 75 个可评分成功输出全部等价于标准答案。该结果只说明
已成功输出样本的数学质量，不能抵消 7 个失败题和 6 个缺失题。
